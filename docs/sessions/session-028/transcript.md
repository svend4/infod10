<a id="m0002"></a>
### m0002 · Ассистент · промежуточное сообщение

Восстановление будет оформлено как отдельная задача с неизменяемым планом и блокировкой. За один шаг она перенесёт ограниченное число файлов; следующий процесс сможет продолжить её с проверенного состояния.

Готовые файлы будут сверяться с планом. Несовпадающие файлы не перезаписываются, а итоговый комплект сохраняет формат предыдущего этапа и постоянный карантин.

<a id="m0003"></a>
### m0003 · Ассистент · промежуточное сообщение

Добавлены команды `prepare`, `step` и `status`. Они отдельно показывают прогресс копирования и завершённый результат.

Пример проверит три ситуации: продолжение задачи в новом процессе, получение результата после отброшенного ответа и чтение готового восстановления без исходного backup. Эти проверки сохранят запрет записи в восстановленную базу.

<a id="m0004"></a>
### m0004 · Ассистент · промежуточное сообщение

При обзоре нашлась важная деталь: совпадения времени и метаданных недостаточно, чтобы признать каталог своим. Добавлена отдельная неизменяемая запись владельца задачи, связанная с каталогом назначения через устройство и inode.

Существующий каталог без такого подтверждения будет отклоняться, даже если его файлы похожи на ожидаемые.

Теперь запускаю пример с отдельными процессами, отброшенным ответом и двумя параллельными вызовами одной задачи. Аварийное завершение процесса в этом сценарии не моделируется.

### Что реализовано

Добавлено пошаговое восстановление базы и архивов:

- `prepare` закрепляет неизменяемый план и каталог назначения.
- `step` переносит ограниченное число файлов.
- `status` восстанавливает прогресс и итоговый ответ.

Принадлежность каталога подтверждается отдельной записью владельца. Чужие или несовпадающие файлы вызывают отказ. Восстановленная база остаётся в карантине: чтение разрешено, изменения и публикация заблокированы.

### Практический результат

Отдельные процессы продолжили восстановление **0 → 1 → 2 → 3 файла**. После отброшенного ответа `status` вернул тот же результат. Готовое восстановление читается без исходного backup. Два параллельных вызова корректно разделили прогресс; получены **16 ожидаемых отказов**.

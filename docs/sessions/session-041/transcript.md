## Часть 1. Отдельное семейство guarded write jobs, обязательный ключ и три квитанции фаз, исторический replay и отзыв, исправление сценария и аудитора, выполненный сценарий, независимые сверки и проверка архива GitHub версии 0.38.0, следующий запрос продолжения

Продолжу с разделения доступа: изучу, как сделать проверку допуска обязательной для выбранного пути записи, и реализую следующий ограниченный этап. Сохраню анализ, код, результаты запуска и новую часть переписки в репозитории.

<a id="m0002"></a>
### m0002 · Ассистент · промежуточное сообщение

Выбран отдельный формат guarded job. В нём старые writer API не смогут выполнить новый шаг: обязательного для них lock-файла не будет, а новый `step` потребует ключ и проверку отзыва.

Каждая из трёх фаз получит отдельную сохранённую квитанцию для точного повтора. Это обязательность среди поддержанных API, а не изоляция произвольного кода: в текущей среде нет прав смены UID. Прежние leases и issuer policy автоматически на новый формат не переносятся.

---

<a id="m0003"></a>
### m0003 · Ассистент · промежуточное сообщение

Новый этап получает отдельный формат задания и квитанции для трёх фаз записи. Параллельно готовятся код, пример и независимый разбор; затем выполню обычный демонстрационный запуск и сохраню результаты вместе с очередной частью переписки.

<a id="m0004"></a>
### m0004 · Ассистент · промежуточное сообщение

Код нового протокола готов к разбору. В нём сохранённая квитанция описывает выполненную фазу, а отдельный `status` показывает текущее состояние. Отзыв ключа должен закрывать и новые шаги, и выдачу прежних квитанций через защищённый `step`.

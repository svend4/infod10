## Часть 1. Подготовка метаданных восстановления без исходного backup, девять прерываний процесса, сохранение staging данных и блокирующих остатков, выполненный сценарий, публикация версии 0.27.0 и следующий запрос продолжения

<a id="m0001"></a>
### m0001 · Ассистент · промежуточное сообщение

Продолжу с ранних прерываний подготовки restore job: до копирования данных, когда ещё создаются план, каталог назначения и запись владельца. Разберу безопасные границы продолжения и реализую следующий этап с явным отказом для неопознанных остатков.

---

<a id="m0002"></a>
### m0002 · Ассистент · промежуточное сообщение

Найдено полезное расширение: завершение подготовки только метаданных без доступа к исходному backup. Сейчас обычный `step` проверяет источник до восстановления этих файлов.

Добавлю отдельную команду `resume-prepare`. Она будет использовать сохранённый план, переносить только метаданные подготовки и сохранять прежний формат ответа. Частичный план, повреждённая запись владельца и каталог без подтверждённого владельца останутся блокирующими.

---

<a id="m0003"></a>
### m0003 · Ассистент · промежуточное сообщение

Команда `resume-prepare` реализована и прошла два независимых статических обзора. Она изменяет только три элемента метаданных подготовки. При уже установленных данных возвращается проверенный status без ремонта.

Архив пополнен частью 29: теперь в нём 284 сообщения. Готовится сценарий девяти прерываний: шесть состояний должны допустить подготовку без источника, а три — сохранить отказ и оставленные файлы.

<a id="m0004"></a>
### m0004 · Ассистент · промежуточное сообщение

Формат status сохранён: и до, и после подготовки метаданных он может показывать `prepared, 0/3`. Поэтому в примере прогресс подготовки будет подтверждаться составом файлов и результатом команды.

Отдельный случай покажет, что `resume-prepare` сохраняет staging данных по наблюдаемым inode, размеру и временным отметкам. Содержимое этого частного файла демонстратор читать не будет.

### m0005 · Ассистент · промежуточное сообщение

Для результатов подготовлена отдельная сверка: 13 завершённых восстановлений и три заблокированные задачи будут проверены по разным ожидаемым состояниям. Частичные записи сохранятся для разбора.

### m0007 · Ассистент · промежуточное сообщение

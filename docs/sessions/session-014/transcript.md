Нашёл показательный случай: проверку «код содержит весь документированный набор методов» можно заменить на «методы кода входят в документированный набор». На текущих одинаковых наборах оба условия дадут `match`, хотя объявленное требование изменилось.

## Что показал анализ

**Полное покрытие новой описи может сохраняться после ослабления самого условия проверки.**

Например, равенство наборов методов заменяется требованием «методы кода входят в документированный набор». На текущих одинаковых наборах обе проверки дают `match`, но объявленный предикат изменился.

Добавлен `requirement-delta`, который отдельно показывает изменения требования, выбранных значений, селекторов и цитаты.

[Подробный анализ, алгоритм и ограничения](https://github.com/svend4/infod10/blob/43d6d4bc911d11ca50259499ee5706d299ce4061/docs/development/requirement-delta.md).

## Выполненные сценарии

| Изменение | Результат разбора |
|---|---|
| Новая цитата | Видно изменение текста |
| Равенство → включение | Ослабление схемы предиката |
| Включение → равенство | Усиление схемы предиката |
| Новая метка области | Структурное изменение |
| Значения 3 → 4 | Разница зафиксирована; направление гарантии не установлено |
| Неверная единица | Блокировка сохранена |
| Устаревшее основание | Блокировка сохранена |

Семь разборов выполнены тремя Python workers: **пять результатов готовы к рассмотрению человеком, два заблокированы**.

[Отчёт и сохранённые основания](https://github.com/svend4/infod10/blob/43d6d4bc911d11ca50259499ee5706d299ce4061/examples/requirement-delta/results/report.md).

Вывод об ослаблении ограничен формальной схемой множеств. Смысловая эквивалентность прозы и поведение программы остаются предметом отдельной проверки. Новых редакторских решений и принятых файлов этот этап не создаёт.

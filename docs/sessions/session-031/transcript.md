## Часть 1. Исторические случаи раннего отказа, явные связи с отдельными попытками, восстановление отброшенных ответов, независимые сверки, публикация версии 0.28.0 и следующий запрос продолжения

<a id="m0001"></a>
### m0001 · Ассистент · промежуточное сообщение

Продолжу с управления заблокированными задачами восстановления. Сначала определю, как безопасно учитывать такие остатки, сохранять причины отказа и связывать повторную попытку с прежней задачей. Затем реализую следующий этап и сохраню результаты в репозитории.

---

<a id="m0002"></a>
### m0002 · Ассистент · промежуточное сообщение

Учёт оформлю как отдельную неизменяемую запись случая. Новая попытка будет создаваться обычной командой `prepare` с явно указанным источником, а затем связываться с этой записью.

Такая связь фиксирует решение оператора. Для повреждённого старого плана нельзя достоверно вывести исходные параметры, поэтому новая попытка получит собственную идентичность.

---

<a id="m0003"></a>
### m0003 · Ассистент · промежуточное сообщение

Согласованы три команды: запись случая, просмотр и связь с уже созданной новой попыткой. Прежние команды восстановления и формат status сохраняются.

При просмотре историческая квитанция будет показана отдельно от текущего состояния файлов. Это позволит видеть, сохранились ли исходные свидетельства и доступна ли связанная попытка, не меняя прежнюю причину отказа.

---

<a id="m0004"></a>
### m0004 · Ассистент · промежуточное сообщение

Демонстратор готов: три случая будут связаны с тремя отдельно подготовленными попытками. Он также проверит восстановление отброшенного ответа через точный повтор и сохранение старых заблокированных файлов.

На один случай предусмотрена одна неизменяемая связь; другая попытка или другой operation ID должны вызвать конфликт. Глобальная уникальность связей между разными случаями этим не устанавливается.

---

<a id="m0005"></a>
### m0005 · Ассистент · промежуточное сообщение

Ядро и CLI прошли независимый статический обзор. Связанная попытка закрепляется по неизменяемым управляющим файлам, а её текущий прогресс наблюдается отдельно. Поэтому обычное копирование DB и архивов не должно сделать связь устаревшей.

Внутри операции не удерживаются две блокировки job одновременно. Наблюдения разных задач последовательны; общей транзакцией они не считаются.

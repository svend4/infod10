## Часть 1. Неизменяемый каталог заданий записи, ограниченные страницы и явные ошибки участников, историческое чтение, независимые сверки, исправление временного аудитора, продолжение сетевой проверки публикации версии 0.33.0 и следующий запрос продолжения

<a id="m0001"></a>
### m0001 · Ассистент · промежуточное сообщение

Продолжу с ограниченного каталога заданий записи: он позволит нескольким обработчикам обходить явный список и видеть состояние каждого задания. Сначала проверю репозиторий и инструкции, затем реализую следующий этап с анализом и прикладным примером.

---

<a id="m0002"></a>
### m0002 · Ассистент · промежуточное сообщение

Каталог будет хранить неизменяемый список заданий с их ID, заявленным участником и решением. Состояния `prepared`, `ready`, `linked` и `completed` будут наблюдаться отдельно на каждой странице.

При исчезновении или изменении задания его строка останется в результате с явной ошибкой. Обход каталога будет только читать состояние; выполнять шаги заданий он не будет.

---

<a id="m0003"></a>
### m0003 · Ассистент · промежуточное сообщение

Каталог и CLI прошли независимое статическое чтение. Для списка сохраняются компактные сведения о заданиях и привязки их неизменяемых записей; полные планы в каталог не копируются.

Готовится пример: новый job останется вне прежнего каталога, а после явного включения в другой каталог его прогресс будет виден без изменения списка участников.

<a id="m0004"></a>
### m0004 · Ассистент · промежуточное сообщение

Пример также покажет создание каталога при временно недоступной цели review: состав захватывается из неизменяемого intent, а недоступность цели отражается уже в странице.

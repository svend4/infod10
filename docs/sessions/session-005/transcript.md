<a id="m0002"></a>
### m0002 · Ассистент · промежуточное сообщение

Нашёл важный случай: документ с полным списком платформ может устареть уже после принятия, когда другой агент добавит новую платформу. Добавлю проверку перед экспортом — такой выпуск будет ждать обновления документа. Граф зависимостей покажет, что именно требует пересборки или повторного ревью и почему.

---

<a id="m0003"></a>
### m0003 · Ассистент · промежуточное сообщение

Граф зависимостей готов. Он различает файлы, где достаточно подставить новое значение, и материалы, которым нужно повторное ревью; для каждого результата сохраняется путь от изменённого утверждения.

Добавляю пример с двумя ситуациями: изменение тайм-аута должно обновить три файла, а добавление платформы — остановить экспорт до исправления полного списка платформ.

### m0004 · Ассистент · промежуточное сообщение

Новый пример выполнен: граф указал три файла из шести при изменении тайм-аута, и именно эти три файла изменились в выпуске. После добавления macOS экспорт остановился из-за устаревшего списка платформ; после обновления документа выпуск сформировался.

Команды анализа, построения графа и сравнения выпусков работают. Поиск по прежнему выпуску также сохранил работоспособность. Это результат одного сценария; ускорение и полнота обнаружения смысловых ошибок пока не измерялись.

## Что добавлено

1. **Граф зависимостей:** источники → утверждения → документы и код → индекс → выпуск.
2. **Анализ влияния:** команда `impact` показывает затронутые файлы и объясняет путь зависимости.
3. **Разделение действий:** какие файлы можно перегенерировать, какие требуют повторного ревью. Эти группы могут пересекаться.
4. **Сравнение выпусков:** команда `compare` различает изменения значений, шаблонов, источников, зависимостей и готовых файлов.
5. **Контроль устаревших принятых материалов:** экспорт останавливается, если существенное основание изменилось уже после принятия документа.
6. **Сохранение зависимостей:** новые выпуски содержат `dependencies.json`; прежний формат поддерживается.


Это позволяет продолжать работу авторов, сохраняя контроль над выпуском: новое утверждение уже принято, а публикация ожидает исправления связанного документа.

## Запуск

Из корня репозитория:

```bash
python3 -m agentwiki impact-demo \
  --workspace /tmp/agentwiki-impact-my-run-01 \
  --workers 6
```

Используйте новый пустой каталог. Пример сохраняет отчёты, граф и три согласованных выпуска.

Граф учитывает **явно объявленные зависимости**. Сокращение набора кандидатов с шести до трёх пока характеризует область изменений; ускорение и полнота обнаружения смысловых ошибок требуют отдельных измерений. Исполнители остаются программными workers без внешних LLM.

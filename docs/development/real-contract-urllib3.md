# Реальный контракт: значения Retry в urllib3 2.5.0

## Зачем добавлен этот материал

Условные сценарии прототипа объясняют координацию, обнаружение пропусков и
устаревание оснований. Следующий вопрос — можно ли поставить столь же
ограниченный, проверяемый вопрос к реальной документации и реализации.
Для этого сохранён [корпус urllib3 Retry 2.5.0](../../corpora/urllib3-retry-v2.5.0/README.md)
с двумя явно выбранными утверждениями. Разбор показывает также место,
где перенос реального контракта в простую формальную модель может исказить
его смысл.

## 2. Первое утверждение: набор методов по умолчанию

[Строки 183–186](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L183-L186)
содержат:

```python
    #: Default methods to be used for ``allowed_methods``
    DEFAULT_ALLOWED_METHODS = frozenset(
        ["HEAD", "GET", "PUT", "DELETE", "OPTIONS", "TRACE"]
    )
```

В [сигнатуре конструктора](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L202-L210)
`allowed_methods` по умолчанию ссылается на этот набор. Утверждение для
нашей описи: **набор `Retry.DEFAULT_ALLOWED_METHODS` содержит перечисленные
шесть методов; POST в нём отсутствует**. Отсутствие POST — вывод из полного
перечисления, а не отдельная цитата автора библиотеки.

Это узкое утверждение о значении конфигурации. Из него нельзя вывести
универсальное обещание «urllib3 никогда не повторяет POST»:

- [Документация параметра](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L127-L134)
  явно описывает `allowed_methods=None` как возможность повторять любой
  метод. Другие условия повтора при этом сохраняются.
- В [ветках `increment()`](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L457-L477)
  ошибка соединения не проверяет `_is_method_retryable`, а ошибка чтения
  проверяет. Документация отдельно связывает ошибки соединения с моментом
  до отправки запроса и ошибки чтения — с моментом после отправки.
- [Проверка метода](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L379-L385)
  возвращает отказ, если задан непустой набор и метод в него не входит.
  Ложные значения не ограничивают эту ветку. Публично документированная
  форма «любой метод» здесь — `None`; `allowed_methods=False` не включён
  в показанную аннотацию и не предлагается нами как поддерживаемый API.

Такое различие существенно для многоагентного редактирования: один агент
может правильно переписать набор, другой — слишком широко пересказать
его как поведенческую гарантию. Проверка равенства литералов обнаружит
ошибку в наборе, но сама не исправит неверный квантор «никогда» в тексте.

## 3. Второе утверждение: `total=10` считает повторы

[Строка 204](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L202-L210)
задаёт `total: bool | int | None = 10`. Докстрока
[строк 70–78](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L70-L78)
говорит:

> Total number of retries to allow. Takes precedence over other counts.

И отдельно:

> Set to ``0`` to fail on the first retry.

Утверждение для нашей описи: **у конструктора `Retry` значение `total`
по умолчанию равно 10; параметр считает повторы, а не все попытки**.
В данных адаптера это `total_default` со смысловой единицей `retries`.
Название `MAX_ATTEMPTS=10` изменило бы смысл выбранного контракта.

Исходная попытка не входит в счётчик повторов. Из значения 10 нельзя
получить гарантию 11 обращений: успешный запрос, неподходящая категория
ошибки и другие условия могут завершить процесс раньше. Для описания
конкретного потока нужно учитывать остальные счётчики, настройки клиента
и ветки обработки. В корпусе не утверждается универсальный предел числа
сетевых операций приложения.

Кроме того, это значение **конструктора `Retry()`**. Оно не означает,
что любой `PoolManager`, приложение или вызов с явно заданным `retries`
использует эту конфигурацию. Сохранённый исходник сам показывает
[отдельную настройку повторов пула и запроса](https://github.com/urllib3/urllib3/blob/aaab4eccc10c965897540b21e15f11859d0b62e7/src/urllib3/util/retry.py#L45-L65).

## 4. Что подготовлено для прототипа

В [source-facts.json](../../corpora/urllib3-retry-v2.5.0/source-facts.json)
сохранены выбранные значения, дословные цитаты с диапазонами строк,
контрольная сумма исходника и существенные оговорки.

[Авторский адаптер](../../corpora/urllib3-retry-v2.5.0/authored/artifact-map.json)
состоит из документа с помеченным JSON-блоком, Python-файла с литералами,
двух обязательств и двух записей описи. Они связывают:

| Поле документа | Литерал адаптера | Отношение |
|---|---|---|
| `default_allowed_methods` | `DEFAULT_ALLOWED_METHODS` | Равенство полного набора строк |
| `total_default` | `TOTAL_DEFAULT` | Равенство целых, область содержит единицу `retries` |

Для первого значения выбран `equals`: целью является сохранение всего
набора значений по умолчанию. Условие «код входит в набор документа»
допустило бы его незаметное сокращение и отвечало бы другому вопросу.

**Перенос выбранных литералов выполнен авторами проекта вручную.**
Реальный исходник содержит класс, вызов `frozenset(...)`, аннотации,
импорты и реализацию методов. Ограниченная грамматика текущего экстрактора
не анализирует такой модуль как конфигурацию. Авторский файл с двумя
литералами не является доказательством, что прототип автоматически извлёк
значения из urllib3 или подтвердил поведение HTTP-клиента.

Материал сохранён для рассмотрения и будущего явного подключения.
Команды продукта над ним не запускались; сохранённый пример миграции
описи использует собственный условный сценарий. Внешние исходники не
импортировались и не исполнялись.

## 5. Что потребуется для следующего практического шага

1. Утвердить область каждого обещания: значение конструктора, параметры
   конкретного клиента или наблюдаемое поведение — разные вопросы.
2. Связать источник и авторский адаптер отдельной записью происхождения:
   кто выбрал фрагмент, какое преобразование выполнил и что осталось вне
   модели. Контрольная сумма исходника не заменяет эту запись.
3. Для автоматизации добавить отдельный ограниченный экстрактор именно
   значения атрибута класса и значения по умолчанию параметра. Его правило
   должно явно описывать допустимые конструкции и возвращать неопределённость
   при неподдерживаемой форме. Исполнение произвольного кода не требуется.
4. Отдельно рассмотреть смысл описаний: различие retries/attempts,
   применимость фильтра методов и условность разрешённого повтора.
5. Сохранять историю изменения описи и оснований при смене версии
   библиотеки. Смена версии не переносит прежнее решение автоматически.

Два выбранных утверждения не составляют полной описи Retry. Их выбор и
адаптер подготовлены ИИ-авторами проекта без независимой разметки
человеком. Корпус не является экспертным эталоном, бенчмарком или
измерением качества системы. Официальные код и документация дают
проверяемое происхождение выбранных данных, но принадлежат одному
проекту и не считаются двумя независимыми подтверждениями.

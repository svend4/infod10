# Guarded review write job: прикладной сценарий

Тридцать восьмой этап agentwiki. [Подробный протокол и анализ](../../docs/development/workspace-restore-case-retention-review-write-guarded.md).

~~~sh
python3 -m agentwiki workspace-restore-case-retention-review-write-guarded-demo --workspace /tmp/agentwiki-review-write-guarded-01 --workers 3
~~~

Пример продолжает прежний issuer demo в новом частном workspace, добавляя отдельный формат задания и обязательный ключ для поддержанного step. Старые write APIs его отвергают. Фазы prepared→ready→linked→completed сохраняют отдельные исторические квитанции; exact replay и отзыв имеют явно разные правила.

[Отчёт обычного запуска](results/restore-case-retention-review-write-guarded-report.md) и публичные JSON сохраняются после завершения сценария. Credentials, private controls, базы, pins и digests остаются вне Git. Пользовательский каталог key должен быть0700, key-файл0600; CLI не принимает secret через аргументы или stdout.

Обязательность ограничена известными поддержанными API. Нет OS isolation файлового владельца, автоматического применения прежних leases/issuer policy, внешней identity или смысловой проверки документации. Число локальных процессов не измеряет ёмкость LLM либо число независимых экспертов.

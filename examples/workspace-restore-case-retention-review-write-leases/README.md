# Локальные аренды позиций write catalog

[Контракт и анализ](../../docs/development/workspace-restore-case-retention-review-write-leases.md) · [машинный отчёт](results/restore-case-retention-review-write-leases-report.json) · [читаемый отчёт](results/restore-case-retention-review-write-leases-report.md).

~~~sh
python3 -m agentwiki workspace-restore-case-retention-review-write-leases-demo \
  --workspace /tmp/agentwiki-review-write-leases-01 --workers 3
~~~

Сценарий использует обычные CLI-команды и отдельные частные SQLite-журналы. Два callers конкурируют за одну позицию, третий выбирает другую. Потерянный ответ восстанавливается точным повтором; освобождение и новый claim дают следующее поколение. Второй независимый журнал может назначить ту же позицию отдельно.

Выбранные jobs уже завершены прежним сценарием. Это показывает границу протокола: claim координирует позицию, не устанавливая наличие pending work. Он не вызывает write step и не блокирует прямой вызов прежнего API. Worker самозаявленный; семантика документа, предметное одобрение, независимость моделей и ёмкость пула здесь не измеряются.

Private controls, исходные pins, контрольные суммы запросов, SQLite-базы и credentials находятся вне публикации. В results сохраняются только безопасные публичные квитанции, отдельные наблюдения, ожидаемые отказы и отчёт выполненного запуска.

# Резервная копия всей рабочей среды

Двадцать четвёртый этап сохраняет текущую DB и полную цепочку архивов в одном частном комплекте. Восстановление предназначено для исторического чтения и сохраняет постоянный карантин базы.

- [Анализ и контракт](../../docs/development/workspace-backup.md).
- [Фактический отчёт](results/workspace-report.md), [машинный отчёт](results/workspace-report.json).
- [Предыдущий этап: цепочка переносов](../source-transfer-chain/README.md).

## Запуск

Python 3.10+, стандартная библиотека и POSIX-права файлов. Из корня существующего checkout:

~~~sh
python3 -m agentwiki workspace-backup-demo --workspace /tmp/agentwiki-workspace-backup-01 --workers 3
~~~

Укажите новый пустой каталог. Предыдущий сценарий выполняется заново; новые публичные материалы получают префикс `workspace-`. Частные базы, архивы, credentials, планы и manifests не публикуются.

## Команды

~~~sh
python3 -m agentwiki workspace-backup create --workspace /private/current --destination /private/full-backup --credential /private/admin.credential
python3 -m agentwiki workspace-backup inspect --bundle /private/full-backup
python3 -m agentwiki workspace-backup restore --bundle /private/full-backup --destination /private/full-restore
~~~

Исходная база должна быть действующей импортированной средой с текущим административным допуском. Восстановленная база находится непосредственно в `state.sqlite3`; рядом лежат частные метаданные и каталог `archives/`.

| Предковые архивы | Два файла, 64 и 38 событий; перенесены точно |
| Продолжение источника | Три авторских задания, композиция, четыре свежих решения и принятие ревизии 5 |

| Недоступность прежних путей | Три исходных каталога переименованы; inspect, restore и историческое чтение прошли |

Пути восстановлены в `finally`. Источник и старые снимки сохранили наблюдавшиеся границы доступа. Отдельно выполнены три обычные команды create/inspect/restore для реального schema 1 комплекта предыдущего этапа: исходные файлы остались прежними, база и архив восстановились побайтно. Эти три команды не включены в счётчик составного демонстратора.

## Границы

Первым создаётся стандартный snapshot intent, защищающий незавершённый путь от инициализации активного Store. Общий manifest появляется последним. Обычный Store может исторически читать уже завершённую карантинную DB до готовности всех внешних архивов; полный inspect требует весь комплект.

Новые изменения и публикация из восстановленной базы заблокированы. Старые leases, grants и решения сохраняются как история, без возобновления прежних полномочий. Это локальный прототип с программируемыми ролями, без внешних LLM, человеческой экспертизы и измерения максимальной нагрузки.

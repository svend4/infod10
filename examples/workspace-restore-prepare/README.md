# Подготовка восстановления без исходного backup

Двадцать седьмой этап продолжает [сценарий прерываний](../workspace-restore-interrupt/README.md). Новая команда `resume-prepare` завершает только метаданные собственного restore job без исходного bundle. DB, архивы, их staging и итоговый workspace manifest она не переносит и не заменяет.

## Запуск

Из корня существующего checkout укажите новое назначение:

~~~sh
python3 -m agentwiki workspace-restore-prepare-demo \
  --workspace /tmp/agentwiki-restore-prepare-01 --workers 3
~~~

Девять отдельных workers достигают фиксированных точек и получают SIGKILL. Шесть состояний допускают подготовку по сохранённому плану; три остаются блокирующими. Частные файлы не исправляются вручную. Последний случай отдельно показывает сохранение staging данных при работе с метаданными.

## Выполненный запуск

Прикладная команда завершилась с первой попытки 21 октября 2026 года в **17:55:38 Europe/Berlin**, каталог `/tmp/infod10-workspace-restore-prepare-development-01`. Сохранены 269 плоских публичных файлов: 260 JSON и девять Markdown. Новых материалов 23: 11 этапов, десять файлов данных и два отчёта; 246 оснований повторены прежним сценарием.

| Граница SIGKILL | Наблюдавшийся исход |
| --- | --- |
| `plan_partial` | Четыре обычные команды отказали; частичный plan сохранён |
| `plan_durable` | Подготовка создана по плану без исходного bundle |
| `intent_durable` | Назначение без owner не принято |
| `owner_partial` | Частичная неизменяемая запись owner сохранена с отказом |
| `owner_durable` | Недостающие метаданные подготовлены без источника |
| `metadata_partial` | Собственный промежуточный префикс пересоздан |
| `metadata_linked` | Известная пара ссылок согласована; готовый intent сохранён |
| `preparation_ready` | Повтор подготовки вернул тот же результат |
| `data_staging_preserved` | Staging данных сохранил inode, размер и временные отметки |

Все девять workers завершились с returncode `-9`. Шесть допустимых задач подготовили метаданные при недоступном источнике: результат остался `prepared, 0/3`, без DB, данных архивов и общего завершающего manifest. После возврата источника обычный step завершил три файла каждой задачи; полный inspect, Store и оба архива сохранили R4/36 событий. Действующая база осталась R5/59. Повтор resume-prepare для готового комплекта сохранил наблюдавшиеся метаданные.

Выполнены 60 новых CLI-вызовов: 48 успешных и 12 ожидаемых отказов, плюс девять workers. Вместе с основанием — 136 CLI и 150 дочерних процессов. Получены 26 отказов нового этапа: 12 CLI, два Store для защищённых незавершённых назначений и 12 enqueue/publish из готовых карантинных DB. Сравнение staging данных основано на lstat; его содержимое демонстратор не читал и побайтовое равенство не заявляет.

Публикуются только безопасные статусы, результаты операций и признаки файловой топологии. SQLite, credentials, планы, owner records, manifests, staging и их хеши остаются в частном каталоге запуска вне Git.

Окно между mkdir назначения и первым intent остаётся неподдерживаемым. Демонстратор не открывает Store в таком пустом назначении. После подготовки обычный step заново проверяет источник перед копированием данных; восстановленный комплект сохраняет карантин.

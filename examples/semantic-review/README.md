# Разбор смысловых изменений

Третий этап проекта добавляет авторский [корпус из 24 случаев](../../corpora/semantic-v1/README.md) и консервативное сравнение структурированных утверждений. [Сохранённый отчёт](results/report.md) показывает четыре выполненных продуктовых разбора. Это иллюстрации, а не оценка точности или тестовая программа.

## Просмотр и анализ

Из корня репозитория, Python 3.10+:

~~~sh
python3 -m agentwiki corpus list
python3 -m agentwiki corpus list --category units
python3 -m agentwiki corpus show --case units-equivalent-seconds-milliseconds
python3 -m agentwiki corpus analyze --case units-equivalent-seconds-milliseconds
~~~

Каждый случай содержит исходное и предложенное утверждения, вымышленные источники с SHA-256, авторское пояснение и ограничения. Аннотации подготовлены ИИ-агентами, экспертом-человеком не проверены и выводятся рядом с результатом без передачи алгоритму сравнения.

## Собственная пара

Создайте JSON с ключами before, after и sources. Быстро получить исходный пример можно так; используйте свободный путь для перенаправления вывода:

~~~sh
python3 -m agentwiki corpus show --case units-equivalent-seconds-milliseconds --pair > /tmp/agentwiki-my-pair-01.json
python3 -m agentwiki review-pair --input /tmp/agentwiki-my-pair-01.json
~~~

Затем измените копию JSON: явно укажите предмет, свойство, условия, вид утверждения, обязательность, отрицание, типизированное значение, атрибуцию, исходный текст и основание. Формат и ограничения описаны в [руководстве](../../docs/development/semantic-corpus.md).

Сравнение не извлекает эти поля из текста. Проверка цитаты устанавливает её буквальное наличие в снимке; поддержку вывода источником и соответствие формулировки полям рассматривает редактор.

## Связь с многоагентным процессом

1. Автор готовит структурированную пару и фиксированные основания.
2. Программный инструмент показывает изменения и основания для осторожности.
3. Проверяющий рассматривает свободный текст, полноту и независимость источников.
4. Согласованное изменение проходит существующий процесс предложения, readset и принятия.
5. Граф зависимостей определяет материалы для повторного рассмотрения.

Новый формат сравнительных утверждений пока является отдельным инструментом. Он не преобразуется автоматически в runtime claims и не обходит Store.review/accept. Результаты всегда содержат requires_human_review=true и auto_accept=false.

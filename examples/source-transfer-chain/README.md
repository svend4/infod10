# Цепочка повторных переносов

Двадцать третий этап сохраняет историю нескольких рабочих сред в новом частном назначении. Текущие документы и код переходят вместе с исходными dependency records; каждый перенос создаёт свежие полномочия.

- [Анализ и контракт](../../docs/development/source-transfer-chain.md).
- [Фактический отчёт](results/chain-report.md), [машинный отчёт](results/chain-report.json).
- [Предыдущий этап](../source-transfer/README.md).

## Запуск

Python 3.10+, стандартная библиотека и POSIX-права файлов. Из корня существующего checkout:

~~~sh
python3 -m agentwiki source-transfer-chain-demo --workspace /tmp/agentwiki-transfer-chain-01 --workers 3
~~~

Укажите новый пустой каталог. Предыдущий сценарий выполняется заново; новые публичные результаты получают префикс `chain-`. Частные базы, архивы, credentials, планы, intent и manifest остаются вне публикации.

## Просмотр происхождения

~~~sh
python3 -m agentwiki store-transfer lineage --workspace /path/to/private/workspace
~~~

Команда сверяет весь комплект и возвращает только безопасные квитанции, workspace ID и число архивов. Активная база изменяется обычными операциями; её первоначальный checksum не сравнивается с текущим файлом. Полные контрольные суммы неизменяемых архивов проверяются отдельно.

## Сохранённый результат

Обычный запуск завершился с первой попытки 21 октября 2026 года в 13:59:51 Europe/Berlin. В `results/` сохранены 169 публичных файлов: 129 заново выполненных оснований предыдущего этапа и 40 новых файлов.

Отдельные обычные команды status и lineage также прочитали реальный schema 1 комплект предыдущего этапа; его четыре основных частных файла остались побайтно прежними.

## Границы результата

Протокол поддерживает до 16 архивов, не более 256 MiB на архив и 1 GiB суммарно, с ограничением времени операции. Это пределы допустимого ввода, без измерения пропускной способности. Стандартный backup новой базы сохраняет только её SQLite-файл; внешний комплект архивов необходимо хранить отдельно.

Обновлённый Store обеспечивает локальные кооперативные проверки. Старые программы, прямой SQL владельца, внешняя маршрутизация и эффекты публикации требуют собственных механизмов. Программируемые роли не устанавливают независимость людей или истинность текста; внешние LLM в примере не вызываются.

# Обязательства документации и конфигурации кода

[Анализ и устройство](../../docs/development/cross-file-obligations.md) описывают ограниченный механизм седьмого этапа. Правило связывает явный JSON-блок документа с литеральной константой кода внутри сохранённого комплекта рассмотрения.

## Запуск

Из корня репозитория, Python 3.10+ и стандартная библиотека:

~~~sh
python3 -m agentwiki obligations-demo --workspace /tmp/agentwiki-obligations-my-run-01 --workers 3
~~~

Используйте новый пустой каталог. Источники вымышленные; авторы и проверяющие — программные исполнители. Внешние LLM не вызываются, предложенный код не выполняется, человеческое заключение не имитируется. SQLite остаётся в рабочем каталоге вне Git.

Сохранённые [отчёт](results/report.md) и [машинный отчёт](results/report.json) относятся к одному выполненному запуску. Новые запуски сохраняйте отдельно от опубликованных результатов.

В сценарии сохранены 4 исходных предложения, 3 композиции, 4 комплекта рассмотрения и 4 анализа обязательства. Журнал содержит 4 пакета, 8 решений и 18 событий. Дополнительно выполнены CLI [анализа варианта с лишним POST](results/cli-analyze-unsafe.json), [записи его самостоятельного отчёта](results/cli-unsafe-obligations.json) и [чтения исправленного результата](results/cli-show-fixed.json).

## Собственное правило

Сначала подготовьте полный review-set с актуальными парами и пакетами по всем файлам. Правило указывает оба файла из `proposal.payload.writes`, идентификатор JSON-блока, путь по ключам JSON-объекта и имя константы Python. Документная метка имеет вид `json agentwiki:retry-policy` в строке открытия fenced-блока.

Поддерживаются `equals` и `code_subset_of_document`. Тип значения задаётся явно: `string`, `boolean`, `integer` или `string_set`. Во втором отношении строки набора кода должны входить в набор документа; направление существенно.

Для команд ниже задайте `OBLIGATION_REVIEW_SET`, `OBLIGATION_SPEC` и новый `OBLIGATION_REPORT` своими путями:

~~~sh
python3 -m agentwiki obligations analyze --review-set "$OBLIGATION_REVIEW_SET" --input "$OBLIGATION_SPEC" --output "$OBLIGATION_REPORT"
python3 -m agentwiki obligations show --input "$OBLIGATION_REPORT"
~~~

Выходной файл не перезаписывается. Для нового наблюдения захватите новый review-set и выполните анализ заново; прежний отчёт сохранит прежние основания.

## Как читать результат

`match` означает выполнение заданного отношения между извлечёнными полями, `mismatch` — обнаруженное несоответствие, `unresolved` — невозможность получить поддерживаемое основание. Например, мутация набора вызовом `.add(...)` делает модуль неподдерживаемым для этого ограниченного экстрактора.

Сопоставление полей и блокеры исходного комплекта выводятся отдельно. Отношение может сохранять `match` при устаревшем чтении runtime. В таком случае общий результат остаётся `blocked`.

Это анализ захваченных кандидатов: `live_state_checked=false`. Совпадение литералов не устанавливает поведение клиента, достаточность источника и соответствие всех фраз документа коду. Всегда сохраняются `requires_human_review=true` и `auto_accept=false`.

# Восстановление после прерывания процесса

Двадцать шестой этап продолжает [пошаговое восстановление](../workspace-restore-job/README.md): отдельный доверенный worker действительно получает SIGKILL внутри файлового шага, а обычная CLI продолжает ту же операцию.

## Запуск

Из корня существующего checkout укажите новое назначение:

~~~sh
python3 -m agentwiki workspace-restore-interrupt-demo \
  --workspace /tmp/agentwiki-restore-interrupt-01 --workers 3
~~~

Сначала повторяется основание предыдущего этапа. Затем пять независимых заданий достигают фиксированных точек: частичный staging, полный staging до установки, известная пара ссылок, все данные до manifest и завершение до ответа. Подтверждение worker предшествует SIGKILL; родитель ожидает завершения, после чего запускает обычные `status` и `step`.

## Выполненный запуск

Обычная команда завершилась с первой попытки 21 октября 2026 года в **17:14:37 Europe/Berlin**, каталог `/tmp/infod10-workspace-restore-interrupt-development-01`. Сохранены 246 плоских публичных файлов: 238 JSON и восемь Markdown. Новых файлов 19: семь этапов, десять файлов данных и два отчёта; прежние 227 оснований созданы повторным запуском предыдущего сценария.

| Точка SIGKILL | Status после завершения worker | Файлы данных | Исход продолжения |
| --- | --- | ---: | --- |
| `staging_partial` | `prepared` | 0 | Собственный неполный staging пересоздан |
| `staging_synced` | `prepared` | 0 | Собственный полный cache установлен заново |
| `target_linked` | `copying` | 1 | Известная вторая ссылка удалена; DB inode сохранён |
| `data_ready` | `ready` | 3 | Manifest завершён без исходного backup |
| `completed` | `completed` | 3 | Результат получен без исходного backup и прежнего ответа |

Все пять workers завершились с returncode `-9`. Выполнены 20 новых обычных CLI и пять workers; вместе с основанием — 76 CLI и 81 дочерний процесс. Десять операций enqueue/publish из восстановленных DB отклонены карантином. История сохранила R4/36 событий и оба архива; действующая среда осталась R5/59.

Read-only status сохранил наблюдавшуюся топологию. В трёх случаях уже установленная DB сохранила устройство/inode после step; в двух ранних случаях DB до продолжения ещё отсутствовала. Независимая частная сверка дополнительно проверила семь завершённых jobs, все метаданные, точный состав архивов, байты данных, принадлежность назначения, карантин, origin и SQLite integrity/fk. Staging-файлов не осталось; частные значения не публиковались.

## Границы

SIGKILL останавливает пользовательский процесс; ОС и хранилище продолжают работать. Пять точек не покрывают все инструкции или повреждения. Полный результат остаётся историческим и карантинным, без права новых записей. Этот пример не измеряет число LLM-агентов, пропускную способность или смысловую точность документов.

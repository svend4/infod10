# Обязательная проверка объявленного содержания

Обычный прикладной сценарий четырнадцатого этапа: фиксированная административная политика связывает документ, конфигурацию кода, цитату обещания и решения проверяющих с точным пакетом. Данные вымышлены, участники запрограммированы локально.

## Запуск

Из корня существующего checkout; нужны Python 3.10+ и стандартная библиотека:

~~~sh
python3 -m agentwiki content-demo --workspace /tmp/agentwiki-content-my-run-01 --workers 3
~~~

Укажите новый пустой каталог. SQLite и credential-файлы сохраняются в `private/`; CLI использует `--workspace /tmp/agentwiki-content-my-run-01/private`. Верхние JSON/Markdown-файлы предназначены для изучения и отдельного экспорта после проверки отсутствия секретов. Каталог `private/` не публикуется.

## Фактический результат

Сохранён запуск `/tmp/infod10-content-development-01` от 16 октября 2026 года. Человеческое время отчёта — Europe/Berlin, технические отметки — UTC/Unix epoch.

| Наблюдение | Результат |
|---|---:|
| Настроенный пул Python workers | 3 |
| Авторские задания / зарегистрированные авторы | 7 / 2 |
| Составные предложения | 6 |
| Участники происхождения принятого кандидата | 3 |
| Этапы / редакторские решения | 16 / 16 |
| Ожидаемые отказы API / заблокированные принятия | 8 / 8 |
| Принятые предложения / конечная ревизия | 1 / 2 |
| События основного сценария | 99 |
| Версия квитанции принятия | 3 |

До активации нового режима обычные одобрения записаны для совпадающего и несовпадающего кода. После активации они остались историей. Новое одобрение требует точный digest текущего пакета. Различие 4 и 5, вычисляемое выражение, отсутствующая либо неоднозначная цитата, неполный и расширенный комплекты заблокировали принятие. Формальное ревью синтаксиса эти предметные отношения не заменило.

Первый подходящий пакет получил одобрения, затем администратор повторно записал ту же политику. Поколение содержания увеличилось с 1 до 2, governance — с 3 до 4. Старые решения не перенеслись; потребовалось новое рассмотрение. Принятие на ревизии 2 закрепило точный пакет в квитанции schema 3. После принятия текущий пакет отражает изменившиеся исходные чтения, а сохранённое историческое тело остаётся прежним.

## Дополнительные команды CLI

После основного сценария выполнены восемь команд на той же частной базе:

1. [Текущий status](results/cli-status-before.json) принятого кандидата.
2. [Исторический show](results/cli-historical-packet-before.json) пакета квитанции: тело сохранено до принятия.
3. [Обновление политики](results/cli-policy-update.json) по [явному входу](results/cli-policy-input.json): в scope добавлена публичная метка `token=public-sample-label` одновременно у обязательства и обещания. Секрета в этой метке нет.
4. [Текущий status после обновления](results/cli-status-after.json): содержание generation 3, governance generation 5.
5. [Повторный исторический show](results/cli-historical-packet-after.json): полное тело совпало с первым чтением.
6. [Повтор прежнего решения](results/cli-decision-replay.json): возвращён старый decision ID и прежняя привязка; действующего голоса для новой политики не появилось.
7. [Governance observe](results/cli-observe.json): публичный ключ scope `token` сохранён, digest полного пакета пересчитан и совпал. Фильтрация имён полей не исказила основание решения.
8. [Повтор принятия](results/cli-accept-replay.json): возвращены прежняя ревизия 2 и прежняя квитанция поколения governance 4, после авторизации по текущему поколению 5.

[Снимок после CLI](results/cli-final-state.json) содержит 101 событие. Добавлены только события изменения двух связанных политик; новых предложений, решений и принятий не создавалось. Основной отчёт сохраняет прежние 99 событий и поколения 2/4.

Всего сохранены 38 основных файлов и 10 дополнительных CLI-файлов, 48 публичных артефактов. Последовательные снимки JSON не образуют общей транзакции; граница нового принятия — `Store.accept`.

## Границы

Пакет проверяет выбранные администратором связи в точном комплекте целиком. Он не обнаруживает все обещания страницы и не доказывает соответствие прозы структурированным полям, истинность фактов, поведение программы или внимательное чтение участником. Локальные principal и bearer-допуски не устанавливают человека, модель или независимую экспертизу. Внешний редакторский журнал сохраняет совещательный статус.

Предлагаемый код разбирается как данные и не исполняется. Внешние LLM, человеческое заключение, измерения качества, нагрузки и программа тестирования отсутствуют. Три workers — размер пула, без измеренной ёмкости портала. SQLite, часы хоста и административная политика доверенные. Внешняя публикация и выпуск приложения выполняются отдельными действиями.

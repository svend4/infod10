# Новая рабочая среда из остановленного источника

Двадцать второй этап переносит принятое содержание в новую базу со свежими полномочиями. Остановленный источник и его история сохраняются; прежние снимки остаются в карантине.

- [Анализ и контракт](../../docs/development/source-transfer.md).
- [Фактический отчёт](results/transfer-report.md), [машинный отчёт](results/transfer-report.json).
- [Предыдущий этап: остановка источника](../source-fence/README.md).

## Запуск

Python 3.10+ и стандартная библиотека, POSIX-права частных файлов. Из корня существующего checkout:

~~~sh
python3 -m agentwiki source-transfer-demo --workspace /tmp/agentwiki-transfer-01 --workers 3
~~~

Укажите новый пустой каталог. Сначала выполняются прежние сценарии; новые результаты сохраняются в файлах `transfer-*`. Базы, история, credentials, intent, manifest, списки запрещённых хешей и другие частные основания остаются вне публикации.

## Протокол

1. Проверить остановленный источник и текущего администратора.
2. Закрепить одно назначение и новый секрет администратора отдельной control-plane reservation. Обычные записи источника остаются запрещёнными.
3. Сохранить полную историю в согласованной частной копии SQLite с прежней меткой остановки.
4. Создать новую базу с sources и принятыми artifacts на текущей ревизии источника.
5. Сохранить исходные dependency records, привязав их к digest импортированных artifacts.
6. Заново включить текущие режимы и политики под новым администратором, завершить частные метаданные назначения.
7. Явно выдать новые роли и аренды; выполнить новые предложения, рассмотрение и принятие.

Начальная импортная ревизия сохраняет номер источника. Это позволяет оставить прежние пять полей dependency record и совместимость release loader. Старые proposal IDs в этих основаниях относятся к историческому архиву; действующими предложениями новой очереди они не становятся.

## Отдельные команды

~~~sh
python3 -m agentwiki store-transfer create --help
python3 -m agentwiki store-transfer status --help
~~~

`create` принимает `--workspace`, `--destination`, исходный `--credential`, `--new-administrator`, отдельный частный `--new-credential` и `--operation-id`. Файл нового секрета должен быть подготовлен заранее с правами 0600. `status` принимает `--workspace` назначения.

Точный запрос повторяется или продолжает собственный опознанный комплект с корректным intent. Неопознанные и повреждённые остатки блокируются. Другое назначение конфликтует. Обычный Store блокирует незавершённый комплект и копию активной базы по другому пути. Исторические fenced/quarantine копии сохраняют чтение по своему отдельному режиму.

Обычный запуск завершился 20 октября 2026 года в 15:08:33 Europe/Berlin. В `results/` сохранены 129 публичных файлов: 97 оснований заново выполненного предыдущего сценария и 32 новых файла переноса. Частные данные и каталоги выпусков в этот плоский набор не входят.

Исходные зависимости совпали с импортными. Выпуски до и после новой работы прошли обычную загрузку; backup новой базы восстановлен в карантин с тем же содержанием и новой квитанцией. Точный replay после изменений вернул первоначальный факт переноса. Число потоков описывает этот запуск и не измеряет предельную ёмкость системы.

## Границы

Старые grants, leases, decisions и operations не копируются в активные таблицы. Частный denylist запрещает повторно выдавать прежние bearer secrets. Полная история остаётся в частном архиве; первоначальные хеши изменяемой рабочей базы служат основаниями завершения переноса, а не условием каждого последующего изменения.

Единственность назначения обеспечивается обновлённым кооперативным Store, локальными путями и источником. Старые бинарные версии, прямой SQL и владелец файлов остаются за этой границей. Протокол не является глобальной службой единственного писателя или автоматическим восстановлением внешних эффектов.

Все роли локальные и программируемые; внешние LLM, человеческая экспертиза и измерение предельного числа агентов в этот сценарий не входят.

# Учёт заблокированных восстановлений

Двадцать восьмой этап продолжает [сценарий подготовки](../workspace-restore-prepare/README.md). Отдельные исторические записи сохраняют причины ранних отказов; явные операторские связи указывают на уже созданные новые попытки.

## Запуск

Из корня существующего checkout укажите новый каталог:

~~~sh
python3 -m agentwiki workspace-restore-case-demo \
  --workspace /tmp/agentwiki-restore-cases-01 --workers 3
~~~

Пример использует три сохранённых блокирующих состояния. Новые job создаются обычным prepare с явно заданным source bundle, затем связываются с case. Исторические записи не заменяют проверку новой попытки и не предоставляют полномочий старой DB.

## Фактический результат

Запуск завершился с первой попытки 21 октября 2026 года в 18:56:13 Europe/Berlin. Сохранены 287 публичных файлов: 277 JSON и 10 Markdown. Из них 269 повторяют основание предыдущего сценария, 18 добавлены этим этапом.

- Три причины: `plan_invalid`, `ownership_unproven` и `owner_invalid`. В первом случае исходная полная identity осталась `null`.
- Три отдельно подготовленные попытки завершили восстановление R4/36 событий и двух архивов. Исторические links сохранили `prepared/0`, а show сообщил текущее `completed/3`.
- Три действительно полученных link-ответа были проверены и отброшены; точный повтор восстановил те же квитанции.
- Все три исходные задачи остались заблокированными и неизменными. Действующая среда сохранила R5/59 событий.
- Выполнены 50 новых обычных CLI: 39 успешных и 11 ожидаемо отказавших. С учётом карантинных операций получены 17 отказов этого этапа.
- Составной сценарий включает 186 обычных CLI и 14 workers прежнего основания: 200 дочерних процессов. Новых прерываний case/link нет.

Финальные show/status, полный inspect и Store новых результатов работали при временно недоступном source bundle; исходное имя возвращено в finally. Это наблюдение готовых результатов. Частичные записи case/link, изменённые либо недоступные старые jobs и предел нагрузки данным запуском не воспроизводились.

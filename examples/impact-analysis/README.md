# Анализ влияния и сравнение выпусков

Продолжение [первого многоагентного примера](../multi-agent/README.md). Здесь реализован следующий шаг: объяснение, какие документы и файлы кода затронуты изменением, и запрет экспорта при устаревших принятых основаниях.

Сохранены [фактический отчёт](results/report.md), [полные данные](results/report.json), [граф JSON](results/graph.json) и [Mermaid](results/graph.mmd). Источники вымышлены, workers программные, LLM не вызываются. Код из предложений не исполняется.

## Воспроизвести

Из корня репозитория, Python 3.10+:

~~~sh
python3 -m agentwiki impact-demo --workspace /tmp/agentwiki-impact-my-run-01 --workers 6
~~~

Нужен новый пустой каталог. Пример повторяет базовую многоагентную работу и продолжает её тремя принятыми изменениями. Существующий каталог с данными не очищается; при повторном запуске укажите другой путь.

## Что произошло в сохранённом запуске

1. Подготовлен базовый выпуск ревизии 9 с зависимостями принятых предложений.
2. До изменения timeout граф выбрал code/client_config.py, docs/reference.md и docs/retries.md — три файла из шести.
3. Принято timeout 40 → 30. В выпуске ревизии 10 фактически изменились эти же три файла.
4. Добавлена macOS. Ранее принятый список платформ требовал нового ревью: изменился результат запроса platforms:api-v1.
5. Экспорт ревизии 11 остановлен с release_needs_review. Ни одного выпуска этой ревизии не создано.
6. Список платформ пересоздан по свежему снимку и принят. Получен выпуск ревизии 12, в котором изменился docs/platforms.md.

Сокращение набора кандидатов 6 → 3 не является измеренным ускорением. Экспорт всё ещё строит полный выпуск; проверки принятия и общие ограничения не отключаются.

## Команды по сохранённым данным

~~~sh
python3 -m agentwiki impact --release examples/impact-analysis/results/release/r9-58b57cc435622fed --changed api.timeout_seconds

python3 -m agentwiki graph --release examples/impact-analysis/results/release/r12-923d5e5a41d54b48 --format mermaid

python3 -m agentwiki compare --before examples/impact-analysis/results/release/r9-58b57cc435622fed --after examples/impact-analysis/results/release/r10-abbdcd6b3af7436c
~~~

Для рабочей базы impact и graph принимают --workspace вместо --release. Параметр --changed можно повторять; поддерживаются также узлы source:fixture-spec и query:platforms:api-v1. Неизвестный узел вызывает ошибку, чтобы опечатка не выглядела отсутствием влияния.

Результат impact содержит affected_files, render_files, review_files и объясняющие paths. Списки рендера и ревью могут пересекаться: один материал способен зависеть и от подставляемого параметра, и от существенного запроса.

## Формат выпуска и совместимость

Новые выпуски используют schema 2: dependencies.json хранит readset, queries и принятую базовую ревизию каждого артефакта. Это сохраняет связи, которые невозможно восстановить только из конечного Markdown. Сохранённый первый пример schema 1 остаётся неизменным и читается с явным предупреждением о неполной истории зависимостей.

Загрузчик проверяет хеши, состав файлов, рендер по knowledge.json, источники, индекс и согласованность оснований schema 2. Самосогласованные контрольные суммы не удостоверяют автора или истинность источника.

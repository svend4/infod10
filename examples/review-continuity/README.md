# Сохранение рассмотрения при несвязанных изменениях

Обычный прикладной сценарий шестнадцатого этапа: старые решения сохраняют силу через доказанные изменения несвязанного раздела. Прежние мнения и полные пакеты остаются неизменяемыми. Все данные вымышлены, роли запрограммированы локально.

## Запуск

Из корня существующего checkout; нужны Python 3.10+ и стандартная библиотека:

~~~sh
python3 -m agentwiki continuity-demo --workspace /tmp/agentwiki-continuity-my-run-01 --workers 3
~~~

Нужен новый пустой каталог. SQLite и credentials сохраняются в `private/` с закрытыми правами; CLI использует `--workspace /tmp/agentwiki-continuity-my-run-01/private`. Верхние JSON/Markdown-файлы экспортируются отдельно после проверки отсутствия секретов. Каталог `private/` не публикуется.

Четыре исходных одобрения A/B сохранили свои ID и локальное основание после изменения раздела D. Полный пакет получил другой адрес. Возражение C также сохранилось через несвязанное изменение и остановило принятие; затем участник явно заменил его на abstain.

Отзыв допуска B убрал его голоса из кворума. Повторная выдача тому же principal старые голоса не восстановила; потребовались новые решения. Изменение выбранной политики A с последующим возвратом не оживило прежние одобрения. Прямой сброс governance с тем же телом политики также потребовал свежего рассмотрения.

После 65 несвязанных обновлений непроверяемая действующая голова C продолжила блокировать принятие. Свежий кворум A/B не устранил этот блокер. Потребовалось явное новое решение C. Последующее несвязанное изменение сохранило готовые одобрения; принятие на ревизии 2 закрепило их в квитанции schema 4 со ссылками на старые и текущий пакеты и переходы цепочки.

Восьмёрка заблокированных принятий и четыре отказа API сохранены как наблюдаемые результаты. Проверки повреждённой истории и форматов дополнительно рассмотрены статически; отдельная программа тестирования отсутствует.

## Дополнительные команды CLI

После основного сценария выполнены восемь команд:

1. [Continuity status](results/cli-continuity-before.json) принятого кандидата.
2. [Content show](results/cli-historical-packet-before.json) пакета квитанции.
3. [Исторический replay одобрения](results/cli-decision-replay.json), вернувший прежний ID и отметку локального основания.
4. [Изменение каталога](results/cli-policy-update.json) по [явному входу](results/cli-policy-input.json): публичная метка `token=public-continuity-label` добавлена только в scope раздела D у обязательства и обещания. Секрета в ней нет.
5. [Continuity status после изменения](results/cli-continuity-after.json): локальное основание совпало, полный адрес пакета изменился, число переходов выросло с 70 до 71.
6. [Observe](results/cli-observe.json): после уже совершённого принятия исходные чтения устарели; живое наблюдение не разрешает новое принятие.
7. [Accepted replay](results/cli-accept-replay.json), вернувший прежнюю ревизию 2 и квитанцию schema 4.
8. [Повторный show](results/cli-historical-packet-after.json): историческое тело осталось прежним.

[Отдельный снимок после CLI](results/cli-final-state.json) содержит 280 событий и поколения содержания/governance 72/76. Добавились три события одного обновления каталога: governance, content и continuity transition. Новых мнений, предложений и принятий не создавалось. Основной отчёт сохраняет прежние 277 событий и поколения 71/75.

Через публичный API отдельно прочитаны все восемь записанных пакетов в [stored-content-packets.json](results/stored-content-packets.json), чтобы ссылки исходных голосов и квитанции были доступны для проверки. Всего сохранены 46 основных файлов, 10 файлов CLI и один экспорт пакетов — 57 публичных артефактов. Последовательные JSON-наблюдения не образуют общей транзакции.

## Границы

Сохранение возможно только при совпадении всего локального основания и каждого промежуточного выбранного контекста. Предел — 64 перехода. Неопределённая история действующего мнения требует свежего решения, отзыва допуска или установленного сброса; возможное veto не исключается ради кворума. Возврат байтов артефакта к прежнему содержимому сохраняет старую семантику digest; обнаружение всех промежуточных изменений данных не заявляется.

Хеш цепочки обеспечивает внутреннюю согласованность, без внешней подписи. SQLite, часы и административная политика доверенные. Локальные principal не удостоверяют человека, модель или независимую экспертизу. Полнота документации, истинность прозы и поведение программы не установлены. Код из предложений не исполняется, внешние LLM и человеческая экспертиза отсутствуют. Размер пула и 65 обновлений не являются измерением пропускной способности или ёмкости портала.

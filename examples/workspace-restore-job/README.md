# Поэтапное восстановление полного комплекта

Двадцать пятый этап закрепляет частный неизменяемый план и переносит данные отдельными ограниченными шагами. Новые процессы продолжают ту же операцию; готовое назначение остаётся в карантине и совместимо с workspace-backup inspect.

- [Анализ и контракт](../../docs/development/workspace-restore-job.md).
- [Фактический отчёт](results/restore-job-report.md), [машинный отчёт](results/restore-job-report.json).
- [Предыдущий этап](../workspace-backup/README.md).

## Запуск

Python 3.10+, стандартная библиотека и POSIX-права файлов. Из корня существующего checkout:

~~~sh
python3 -m agentwiki workspace-restore-job-demo --workspace /tmp/agentwiki-restore-job-01 --workers 3
~~~

Укажите новый пустой каталог. Предыдущий сценарий выполняется заново; новые публичные файлы получают префикс `restore-job-`. Частные планы, базы, архивы, credentials, metadata и staging не публикуются.

## Команды

~~~sh
python3 -m agentwiki workspace-restore prepare --bundle /private/full-backup --destination /private/restored --job /private/restore-job --operation-id recovery-01
python3 -m agentwiki workspace-restore step --job /private/restore-job --limit 1
python3 -m agentwiki workspace-restore status --job /private/restore-job
~~~

Job и назначение должны быть соседними каталогами одного частного родителя. Исходный полный bundle может находиться отдельно. Один шаг переносит до 16 файлов, по умолчанию один; полный комплект содержит DB и до 16 предковых архивов.

## Сохранённый результат

Обычный запуск завершился с первой попытки 21 октября 2026 года в 16:30:02 Europe/Berlin. Сохранены 227 публичных файлов: 203 основания предыдущего сценария и 24 новых файла.

| Наблюдение | Результат |
| --- | --- |
| Пошаговое копирование | 0 → 1 → 2 → 3 файла, отдельные CLI-процессы |
| Промежуточная DB | Ревизия 4 доступна для чтения; запись и полный inspect до окончания заблокированы |
| Отброшенный ответ | Завершённый ответ восстановлен точно через status |
| Недоступность источников | Backup и три прежних каталога временно переименованы; status, step и чтение готового комплекта прошли |
| Параллельные процессы | Два CLI-вызова одной второй задачи дали прогресс 1 и 2, затем перенос завершён |
| Состояние | Restore сохранил ревизию 4 и 36 событий; живой источник — ревизию 5 и 59 событий |
| CLI и отказы | 18 новых процессов, всего 56; 16 ожидаемых отказов |

Оба завершённых назначения имеют прежний формат из шести записей. Их DB и два архива совпали с исходными файлами побайтно; планы и owner records остались в отдельных job directories. Имена временно перемещённых каталогов восстановлены в `finally`.

## Границы

Проверенные готовые файлы переиспользуются; несовпадающие файлы не перезаписываются. Внешний job хранит план и собственный staging, а в завершённом назначении остаётся прежний формат из шести записей. Полный manifest появляется после проверки всех данных.

После первой атомарной установки DB её постоянный карантин разрешает историческое чтение. Полный inspect требует все архивы и завершение. Завершённый status и повтор step читают результат без исходного bundle; для недостающих файлов нужен неизменённый проверенный источник.

Восстановление произвольных чужих остатков и всех аппаратных сбоев не заявляется. Программируемые роли не устанавливают истинность содержания или независимость людей; измерений предельной нагрузки нет.

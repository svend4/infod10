# Редакционное согласование нескольких агентов

Четвёртый этап продолжает [разбор смысловых изменений](../semantic-review/README.md). Автор фиксирует пару утверждений, снимки источников и результат анализа в неизменяемом пакете. Проверяющие записывают решения именно по этому пакету, сохраняя предыдущие решения и объяснения.

Демонстрация использует программных агентов, вымышленные источники и стандартную библиотеку Python. Внешние LLM не подключены. Человек в демонстрации не участвует; согласие агентов не обозначается как человеческое или окончательное принятие.

## Запуск

Из корня репозитория, Python 3.10+:

~~~sh
python3 -m agentwiki editorial-demo --workspace /tmp/agentwiki-editorial-my-run-01 --workers 3
~~~

Нужен новый пустой каталог. Существующие данные не удаляются; для следующего запуска задайте другой путь. Значение workers от 1 до 32 задаёт размер пула, а не число независимых моделей. В первой фазе в пул передаются два задания; при workers=1 они выполняются последовательно. Третий агент действует на последующих этапах.

В workspace появятся editorial.sqlite3, journal.json, report.json и report.md. JSON сохраняет пакеты, решения, результаты отдельных действий и журнал событий; Markdown объясняет наблюдавшиеся переходы. Локальные идентификаторы и время формируются во время запуска.

## Сценарий

1. Автор proposal-agent создаёт пакет из случая «30 секунд и 30 000 миллисекунд». Авторская аннотация корпуса в анализ не передаётся.
2. Два программных проверяющих отправляют approve для одного packet_digest. Появляется agent_agreement; человеческое рассмотрение остаётся обязательным.
3. Третий агент отправляет request_changes. Совместно с сохранёнными approve это образует disagreement.
4. Третий агент уточняет своё объяснение и заменяет собственное решение на approve. Новая запись ссылается на предыдущую через supersedes; исходное замечание остаётся в истории.
5. Повтор точно той же операции возвращает прежнее решение с replayed=true. Новая запись решения не добавляется.
6. Попытка обновления на основе устаревшего предыдущего решения получает decision_conflict.
7. После добавления предложения в after.text старый пакет получает stale_input, хотя структурированные количества и источники не изменились.
8. Для обновлённой пары создаётся отдельный пакет со статусом awaiting_reviews. Решения старого пакета в него не переносятся.

## Что означает результат

Журнал раздельно показывает актуальность входных данных, текущие решения агентов и наличие записанного человеческого решения. Во всех этапах этой демонстрации requires_human_review=true, human_review_recorded=false и auto_accept=false.

Совпадение структурированных значений не устанавливает истинность текста. Согласие запрограммированных участников не является независимой экспертизой. Точное сравнение входных снимков замечает изменение формулировки, но не оценивает смысл добавленного текста.

Акторы и их типы пока задаются локально и не удостоверяют личность. Цепочка хешей связывает сохранённые события; она не заменяет аутентификацию, внешнее заверение или экспертную оценку. Журнал не вызывает Store.accept и не публикует выпуск документов или кода.

# Сборка вкладов и рассмотрение всего предложения

[Руководство и анализ](../../docs/development/composed-review.md) описывают шестой этап проекта. Два программных автора подготавливают изменения существующих документа и файла Python. Интегратор сохраняет новое составное предложение; проверяющие рассматривают его записи через отдельные пакеты.

## Запуск

Из корня репозитория, Python 3.10+ и стандартная библиотека:

~~~sh
python3 -m agentwiki review-set-demo --workspace /tmp/agentwiki-composed-my-run-01 --workers 3
~~~

Нужен новый пустой каталог. SQLite-базы остаются в нём вне Git. Предлагаемый код сохраняется как данные и не исполняется; внешние LLM не вызываются. Человеческое заключение не имитируется.

Сохранённые [отчёт](results/report.md) и [JSON](results/report.json) относятся к одному обычному запуску демонстрации. Новые запуски сохраняйте отдельно от опубликованных результатов.

В запуске сохранены два исходных предложения, одна композиция и три комплекта рассмотрения. В журнале — 2 пакета, 5 решений и 11 событий. Дополнительно выполнены CLI [создания](results/cli-create.json), [повторной оценки](results/cli-recheck.json) и [повтора композиции](results/cli-compose-replay.json). Создание [нового снимка](results/current-review-set-cli.json) после изменения тайм-аута сохраняет `blocked`; оно не обновляет устаревший proposal.

## Собственный комплект

В runtime должен существовать proposal. В журнале должны существовать пакеты по его файлам. JSON-дескриптор содержит список уникальных привязок:

~~~json
[
  {"artifact_id": "docs/reference.md", "packet_id": "pkt_…", "pair": {"before": {}, "after": {}, "sources": {}}}
]
~~~

Это схема дескриптора, не готовая пара: поля `before` и `after` нужно заполнить по [формату утверждений](../../docs/development/semantic-corpus.md). Их `text` должен буквально совпадать с исходным и предлагаемым шаблонами. Для полного предложения добавьте все его файлы, включая код.

Для команд ниже задайте `REVIEW_WORKSPACE`, `REVIEW_JOURNAL`, `PROPOSAL_ID`, `BINDINGS_FILE` и новый `REVIEW_SET_FILE` своими значениями:

~~~sh
python3 -m agentwiki review-set create --workspace "$REVIEW_WORKSPACE" --journal "$REVIEW_JOURNAL" --proposal "$PROPOSAL_ID" --bindings "$BINDINGS_FILE" --output "$REVIEW_SET_FILE"
python3 -m agentwiki review-set recheck --workspace "$REVIEW_WORKSPACE" --journal "$REVIEW_JOURNAL" --input "$REVIEW_SET_FILE" --bindings "$BINDINGS_FILE"
~~~

Первый вызов сохраняет новый файл без перезаписи. Второй выводит новое наблюдение, сохраняя исходный комплект. Для смены привязок к пакетам создайте новый комплект; повторная оценка сохраняет выбранные идентификаторы и допускает новый текущий вход пары.

## Границы результата

Полное покрытие означает, что перечислены все записи proposal. Смысловая достаточность источников, соответствие заданных полей свободному тексту и корректность поведения программы этим не установлены. Решения и типы участников самозаявленные.

Сборка не переносит прежние одобрения. Согласованный комплект остаётся материалом для человека: `requires_human_review=true`, `auto_accept=false`, `atomic_capture=false`. Решения из отдельной базы журнала не превращаются в разрешение `Store.accept`.

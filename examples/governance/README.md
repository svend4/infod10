# Локальные допуски и обязательная политика принятия

Прикладной сценарий двенадцатого этапа использует отдельную новую SQLite-базу и вымышленные документ и конфигурацию. Зарегистрированные principal являются программными участниками. Владение credential разрешает локальную операцию; личность человека, предметная компетентность и истинность текста этим не удостоверяются.

## Запуск

Нужны Python 3.10+ и POSIX с `O_NOFOLLOW`. Из корня существующего checkout:

~~~sh
python3 -m agentwiki governance-demo \
  --workspace /tmp/agentwiki-governance-my-run-01 --workers 3
~~~

Используйте новый пустой каталог. Для публикации сохранён запуск `/tmp/infod10-governance-development-02`; предварительный `-01` остаётся вне Git. Окончательный запуск выполнен после завершения статической проверки и добавления индекса таблицы повторов операций.

## Выполненный результат

[Отчёт](results/report.md), [полный JSON](results/report.json).

Два программных автора подготовили три вклада, интегратор создал одну композицию. Политика требует двух действующих principal по каждому файлу и отдельного координатора. Сохранены 16 решений, 14 этапов и 52 события исходного прикладного запуска.

| Ситуация | Наблюдение |
|---|---|
| Формальное ревью есть, governance-одобрений нет | Принятие заблокировано |
| Два credential одного principal | Засчитывается один проверяющий |
| Документ одобрен, у кода нет второго голоса | Принятие заблокировано |
| Последний голос — `request_changes` | Действует veto |
| Замена с прежним CAS | Запрос отклонён |
| Допуск отозван и выдан заново | Старые голоса не оживают |
| Сменилось поколение политики | Нужны новые решения |
| Все условия выполнены | Композиция принята, ревизия 1 → 2 |
| Повтор принятого proposal | Прежняя ревизия и квитанция |
| Replay с отозванным coordinator credential | Доступ отклонён |
| Свежие одобрения старого конкурирующего документа | `stale_read` продолжает блокировать принятие |

Шесть ожидаемых отказов API сохранены в [операциях](results/operations.json). Они относятся к отсутствующему credential, области допуска, отсутствию неявных полномочий администратора, устаревшему CAS и отозванному координатору. Истечение срока во время длинного рассмотрения разобрано статически; отдельный сценарий истечения в этом запуске не выполнялся.

## Отдельные CLI-вызовы

После исходного запуска выполнены восемь команд:

1. [Выдача дополнительного reviewer-допуска](results/cli-grant.json).
2. [Точный повтор выдачи](results/cli-grant-replay.json) с тем же `expires_at` и подготовленным секретом.
3. [Отзыв дополнительного допуска](results/cli-revoke.json).
4. [Публичный status](results/cli-status.json).
5. [Наблюдение политики конкурирующего proposal](results/cli-observe-competing.json).
6. [Попытка его принятия](results/cli-accept-competing.json).
7. [Авторизованный replay принятой композиции](results/cli-accept-replay.json).
8. [Точный replay существующего решения](results/cli-decision-replay.json).

У конкурирующего proposal наблюдение политики даёт `eligible=true`, но попытка принятия сохраняет `accepted=false` и `stale_read`. `observe` проверяет только полномочия и мнения; полные проверки runtime выполняются в `accept`.

Выдача, отзыв и заблокированная попытка добавили три события. [Экспорт после CLI](results/cli-events.json) содержит 55 событий. Исходный отчёт с 52 событиями сохранён без изменения. Ревизия осталась 2; дополнительные решения и принятия не создавались.

Пример чтения существующего прикладного workspace:

~~~sh
python3 -m agentwiki governance status \
  --workspace /tmp/agentwiki-governance-my-run-01/private
~~~

Для авторизованных команд нужен соответствующий частный credential-файл. Обязательные параметры и формат политики описаны в [руководстве](../../docs/development/governance.md).

## Секреты и границы

В `results` находятся 29 публичных прикладных файлов и девять файлов дополнительных CLI-результатов. SQLite-база и credential-файлы остаются в частном подкаталоге рабочего запуска. Они не копируются в Git. Их названия в отчёте описывают расположение только внутри выполненного workspace.

Начальный администратор бессрочен, владелец БД доверен. Авторство proposals остаётся самозаявленным; отдельного запрета governance-голоса автора нет. Несколько principal могут принадлежать одному человеку. Отзыв или истечение допуска прекращает действие его veto. Эти свойства являются явными границами локальной политики.

Предложенный код не исполнялся, внешние LLM и человеческое заключение не имитировались. Принята только вымышленная композиция; release и внешняя публикация приложения отсутствуют. Число workers не является измеренной ёмкостью, независимостью экспертизы или выигрышем времени. Испытания нагрузки и программа тестирования не проводились.
